# Parthia Health — Project Handoff

_Last updated: 2026-09-11. Written to give another assistant or engineer full context on the prototype: what it is, how it is built, how it works, where it runs, and what comes next._

---

## 1. What Parthia Health is

Parthia Health is a **patient-owned, holistic medication-safety platform** for people living with several chronic conditions who take five or more medicines (polypharmacy). The first focus is cardiometabolic disease: type 2 diabetes, hypertension, cardiovascular disease, and the mental-health conditions that commonly travel with them.

The core idea: a patient's medication list, their own daily entries (symptoms, mood, meals), and their labs are checked together by a **transparent, rule-based safety engine**. Anything it finds is surfaced as a plain-language explanation plus a **question to raise with the doctor**, never an instruction to change treatment. Four domains (Medication Safety, Physical & Labs, Mental Health, Nutrition) are shown as **separate indicators**, deliberately never combined into one score.

### Purpose of this build

This is a **phase-1, demo-quality prototype**, used for:

- pitching to potential partners (health systems, payers, pharmacies, investors)
- an exhibit in an immigration petition (evidence of original technical work)

It is **not** a production or clinical system. It uses **synthetic data only**. There is no real EHR/FHIR integration, no real authentication, no trained ML model, no database, and no real language model. Each of those has a clearly marked seam in the code where it plugs in later.

## 5. Data model (`src/lib/types.ts`)

All types are real TypeScript interfaces shared by mock data, engine and UI. FHIR R4 analogues are noted so the mapping layer is obvious later.

| Type | Key fields | FHIR analogue |
| --- | --- | --- |
| `Patient` | `id, name, age, sex, conditions[], medications[], summary, primaryClinician, medicationHistory[], labs[], vitals[]` | Patient + linked resources |
| `Condition` | `name, category (diabetes/hypertension/cardiovascular/mental-health/other), code (ICD-10), diagnosedOn` | Condition |
| `Medication` | `id, name, genericName (lower-case, used for rule matching), class (MedicationClass union of ~30 classes), dose, frequency, startDate, indication, rxNormCode?` | MedicationStatement |
| `MedicationEvent` | `date, medicationName, type: started / dose-changed / stopped, detail` | MedicationStatement history |
| `LabResult` | `name, value, unit, date, referenceRange {low?, high?}, status: normal / borderline / abnormal` | Observation (lab) |
| `VitalSign` | `timestamp, systolic, diastolic, heartRate, weightKg` | Observation (vitals) |
| `SymptomEntry` | `timestamp, symptom, severity 1–5, note` | Observation (patient-reported) |
| `MoodCheckIn` | `timestamp, score 1–5, note` | Observation (patient-reported) |
| `NutritionEntry` | `timestamp, meal (breakfast/lunch/dinner/snack), description, tags[]` where `NutritionTag` = `high-vitamin-k, grapefruit, high-sodium, high-sugar, high-potassium, alcohol, caffeine, balanced` | Observation (patient-reported) |
| `RiskFlag` | `id, patientId, ruleId, category, severity (low/moderate/high), title, medications[], explanation, suggestedNextStep, evidence[], detectedAt` | DetectedIssue |
| `RiskCategory` | `drug-drug`, `drug-nutrient`, `drug-mood`, `anticholinergic-burden` | — |
| `PatientRecord` | `{ patient, symptoms, moods, nutrition }` — the unit the engine evaluates | Bundle |
| `DomainIndicator` | `domain, label, level (good/watch/attention), headline, detail, metric?` | — |

Nutrition tags are a closed set on purpose: rules match on tags, and a real food database would map onto them.

## 7. Safety engine (`src/lib/safetyEngine/`)

**Contract:** `evaluatePatient(record, { now?, ruleIds? }) → RiskFlag[]`, sorted high → moderate → low, then by title. Every rule is a pure function `(record, ctx: { now }) → RiskFlag[]`. `RULES` is the exported list (9 rules) and is rendered in the UI ("How the safety check works" on the Medications page, and on the About page) so the logic is inspectable.

Every flag:
- names its `ruleId`
- lists `evidence[]` (the concrete data points used)
- has a plain-language `explanation`
- has a `suggestedNextStep` **always phrased as a question for the doctor/pharmacist**

Shared helper: `withinLastDays(items, days, now)` uses **calendar-day semantics** (today counts as day 1, so "last 14 days" = today + 13 prior days).

### 7.1 Drug–nutrient (`rules/drugNutrient.ts`, lookback 28 days)

| Rule id | Fires when | Severity |
| --- | --- | --- |
| `drug-nutrient/warfarin-vitamin-k` | Warfarin on list, ≥10 logged nutrition days; buckets `high-vitamin-k` days per week (4 weeks). **Swing** if max−min ≥ 3 days/week; **very low** if total ≤ 1 day. | swing: high if INR lab is abnormal, else moderate; very low: low |
| `drug-nutrient/statin-grapefruit` | A statin on list and any `grapefruit` tag logged. Uses `GRAPEFRUIT_STATIN_SENSITIVITY` (simvastatin/lovastatin high, atorvastatin moderate, rosuvastatin/pravastatin/fluvastatin/pitavastatin minimal → skipped). | high / moderate by sensitivity |
| `drug-nutrient/ace-potassium` | ACE inhibitor or ARB and `high-potassium` on ≥3 days | low |
| `drug-nutrient/metformin-alcohol` | Metformin and `alcohol` on ≥2 days | low |

### 7.2 Anticholinergic / polypharmacy burden (`rules/burden.ts`)

| Rule id | Fires when | Severity |
| --- | --- | --- |
| `burden/polypharmacy-count` | ≥ `POLYPHARMACY_THRESHOLD` (10) active meds | moderate |
| `burden/multiple-psychotropics` | ≥2 meds whose class is in `PSYCHOTROPIC_CLASSES` (ssri, snri, tricyclic, benzodiazepine, z-drug, antipsychotic) | moderate if age ≥65 else low |
| `burden/anticholinergic-score` | Sum of `ANTICHOLINERGIC_BURDEN[genericName]` (ACB scale 1–3, illustrative subset) ≥ `ACB_SIGNIFICANT_THRESHOLD` (3). Also counts matching symptoms in last 14 days (dry mouth, foggy, forgetful, confusion, constipation, blurry). | high if total ≥5, or ≥3 with ≥3 matching symptom entries; else moderate |

### 7.3 Drug–mood (`rules/moodAdherence.ts`)

`drug-mood/decline-after-change`: for each `MedicationEvent` in the last 60 days with ≥14 days of follow-up, compare mean mood in the 14 days **before** the change (needs ≥5 check-ins) with mean mood **since** (needs ≥7). Fires if decline ≥ 0.8 points, **or** least-squares slope ≤ −0.04/day and last-week mean < baseline − 0.5. Severity **high** if last-week mean ≤ 2.5, else moderate. The explanation also nudges about adherence (low mood is a common reason people stop taking medicines).

### 7.4 Drug–drug (`rules/drugDrug.ts`, table in `knowledge.ts`)

`drug-drug/known-pairs/<pairId>` for each pair in `DRUG_DRUG_PAIRS` where both sides match (by generic name or class). Pairs with `aggravatingSymptoms` look for those words in the last 14 days of symptoms; **low-severity pairs only fire when a matching symptom exists.**

| Pair id | A | B | Severity |
| --- | --- | --- | --- |
| `warfarin+antiplatelet` | warfarin | antiplatelet or NSAID class | high (symptoms: bruising, nosebleed, bleeding) |
| `warfarin+amiodarone` | warfarin | amiodarone | high |
| `ace+potassium-sparing` | ACE-i/ARB | potassium-sparing diuretic | moderate |
| `ssri+zdrug-sedation` | SSRI/SNRI | z-drug, benzodiazepine, antihistamine | moderate (symptoms: foggy, dizziness, fall, drowsy) |
| `sulfonylurea+beta-blocker` | sulfonylurea/insulin | beta-blocker | low |
| `multiple-bp-lowering+dizziness` | ACE-i/ARB/diuretic | beta-blocker/CCB/nitrate | low (requires dizziness) |

The knowledge tables are small and illustrative; they are the seam for a licensed drug-interaction database.

## 8. Domain indicators (`src/lib/status/indicators.ts`)

`computeIndicators(record, flags, now)` returns four `DomainIndicator`s, each with level `good | watch | attention`. They are **never combined**.

| Domain | attention when | watch when |
| --- | --- | --- |
| Medication Safety | any high flag | any moderate flag |
| Physical & Labs | ≥2 abnormal labs, or ≥3 severe (≥4/5) symptom entries in 7 days | 1 abnormal lab, or ≥2 borderline, or avg symptom severity ≥3 |
| Mental Health | 7-day mood mean < 2.6 | mean < 3.3, or dropped ≥0.6 vs previous 2 weeks, or no check-ins |
| Nutrition | logged < 60% of last 14 days **and** a diet concern | logging gaps, or diabetic with sweet snacks ≥4/14 days, or cardio/HTN with salty meals ≥7/14 days |

## 10. Assistant (`src/lib/assistant/index.ts`)

Interface:
```ts
interface AssistantProvider { name: string; respond(question, { record, flags, now }): Promise<AssistantReply> }
interface AssistantReply { text; sources: string[]; suggestions?: string[]; urgent?: boolean }
export const assistant: AssistantProvider = scriptedProvider;
```

`scriptedProvider` matches keywords in this order: emergency phrases (chest pain, can't breathe, suicidal…) → urgent message with 911/988, no data; a medication mentioned by name → its details + related flags; greeting; "what medications"; recent changes; flags/risk/interaction; mood; food/nutrition/grapefruit/vitamin K; symptoms; labs/INR/A1c/BP; doctor/appointment/share (lists every flag's question); install/notifications; fallback. Every reply is assembled only from the current `PatientRecord` and its flags. The UI labels everything "AI-generated" regardless of provider, so the disclosure survives the swap to a model.

## 11. PWA and notifications

### Manifest (`public/manifest.json`)
name "Parthia Health", short_name "Parthia", `display: standalone`, `start_url: /`, `theme_color: #0E5C56`, `background_color: #F7F4EE`, icons 192/512 (`any`) + maskable 192/512, shortcuts to `/medications/` and `/trends/`. Linked via `metadata.manifest` in `layout.tsx`; `viewport.themeColor` and `appleWebApp` metadata are also set.

### Service worker (`public/sw.js`, cache version `parthia-v2`)
- **install:** precache app shell — `/`, `/medications/`, `/trends/`, `/share/`, `/assistant/`, `/install/`, `/about/`, manifest, icons (`Promise.allSettled` so one miss doesn't abort).
- **fetch:** navigations → network-first, fallback to cache (tries trailing-slash variant, then `/`); `/_next/static/*`, `/icons/*`, and png/svg/ico/woff2/css/js → cache-first with background fill.
- **push:** shows a notification from the JSON payload `{title, body, url}`.
- **message `SCHEDULE_NOTIFICATION`:** `setTimeout` → `showNotification` (local reminders).
- **notificationclick:** focuses an open window and navigates to `data.url`, or opens a new one.
- Registered by `PWAProvider` on mount. Because mock data ships inside the JS bundles, caching the shell makes the whole demo work offline.

### Install flow (`lib/pwa/useInstall.ts`, `components/InstallCTA.tsx`)
- Module-level store: `beforeinstallprompt` is captured **at module load** (it can fire before any component mounts), `appinstalled` and `display-mode` changes update the snapshot; React reads via `useSyncExternalStore` with a server snapshot `{ready:false}` to avoid hydration mismatch.
- **Android / desktop Chromium:** `canPrompt` → button calls `promptInstall()`.
- **iOS Safari:** no prompt exists → button links to `/install/`, which shows the designed three-step walkthrough (Share icon → "Add to Home Screen" row → "Add"). `isStandalone()` checks `display-mode: standalone` and `navigator.standalone`.
- Header CTA renders only when `ready && !isInstalled`; dashboard also shows a banner variant.

### Notifications (`lib/pwa/push.ts`, `components/NotificationSettings.tsx`)
- Gating: on iOS and not standalone → "Install first" message (iOS 16.4+ only allows push for Home Screen apps); no `Notification` API → unsupported.
- `enableNotifications()` (must run from a tap): `Notification.requestPermission()`; if granted **and** `NEXT_PUBLIC_VAPID_PUBLIC_KEY` is set → real `pushManager.subscribe()` with the VAPID key, subscription JSON stored in `localStorage` (`parthia.pushSubscription`) — the missing piece is a `POST` to a reminder service (marked `TODO(phase 2)`). Without a key → `local-only` mode.
- Reminder settings (`parthia.reminders`): enabled, medication time (default 08:00), check-in time (default 20:30). `scheduleDailyReminders()` posts two `SCHEDULE_NOTIFICATION` messages to the SW; re-armed on every app launch by `PWAProvider`. Buttons: "Send a test reminder now", "Test a nudge in 10 seconds".

### Conventions and gotchas
- Never `setState` synchronously inside `useEffect` (lint error). Use `useSyncExternalStore` for browser state, lazy initialisers for one-time reads, or `next/dynamic` with `ssr:false` for client-only components.
- `LayoutProps<"/">` is a generated global type; use `{ children: React.ReactNode }` so `tsc --noEmit` works standalone.
- Static export forbids dynamic routes without `generateStaticParams`, route handlers, server actions, redirects/headers in `next.config`, and default image optimisation.
- `trailingSlash: true` means internal links end with `/` (`/medications/`). The SW precache list and `AppShell` nav use those forms.
- When adding a route: add it to `SHELL_URLS` in `sw.js` and bump `VERSION` so installed clients refresh.
- Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` when Claude authored the change.
